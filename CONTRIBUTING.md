# Contributing Guidelines

Thank you for checking out this polyglot playground! Contributions to expand this project to new languages or optimize current setups are highly encouraged.

## Ground Rules

To ensure consistent comparisons between language variations, all implementations must follow these constraints:

1. **Zero External Dependencies:** You may only use tools provided out-of-the-box by the language's built-in standard library toolchain. No third-party packages, external modules, or web frameworks.
2. **Deterministic Custom LCG:** You must not use the standard library's random engine (e.g., Python's `random`, JS's `Math.random`). Instead, reuse the time-seeded 64-bit LCG logic:
   - **Multiplier:** `6364136223846793005`
   - **Increment:** `1442695040888963407`
   - **Overflow:** Must explicitly truncate or mask to 64 bits (`& 0xFFFFFFFFFFFFFFFF`) if the language supports arbitrary-precision integers natively.
3. **Synchronous/Blocking Inputs:** The game loop must remain synchronous, blocking execution sequentially while waiting for user movement commands.

## Submission Workflow & Cleanliness

If you want to add a new language implementation:

1. Fork the repository.
2. Create a dedicated directory named after the language (e.g., `/java`, `/go`).
3. Include standard project layout manifests if needed (e.g., for Java, include a standard `pom.xml` or `build.gradle` along with the standard directory architecture).
4. Add a code comment header inside your source files detailing execution commands for both Linux/macOS and Windows environments.
5. **Keep the Repository Clean:** Update the global `.gitignore` file to include all intermediate build directories, binaries, and local development configurations generated by your addition (e.g., adding `/target/` for Rust, `*.exe`, `*.out`, `/bin/`, `/build/`, or `.idea/` paths). No compiled artifacts should ever be committed.
6. Update the `README.md` links and list to document your new addition.
7. Submit a detailed Pull Request.
